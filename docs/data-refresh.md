## 统一机制

- `data-sync.ts` 只合并相同的在途读取，不缓存已完成业务响应。相同参数在前一次完成后仍会重新请求。
- 每次读取拥有递增序号，只有最新请求能提交结果、错误及加载结束状态；离开/销毁页面使旧读取失效。成功写入和窗口重新可见推进读取版本，写入前/隐藏前的读取不能满足后一次刷新。
- `scoped-refresh.ts` 负责首次进入、KeepAlive 激活、窗口焦点及可见性返回。资源更新通知会标记依赖页面，活动页重新验证，缓存页在再次激活时重新读取。旧刷新周期不能解锁或覆盖较新周期；等待期间收到新意图会继续读取，再解除遮挡。
- 同一轮 focus/visibility 及重复请求合并处理，没有全 SPA 刷新或新增全站轮询。跨独立会话的修改在再次进入页面、打开操作窗口或返回窗口时从服务端重新读取。
- 只有 HTTP 成功且响应可读取的业务写入才发送失效通知；失败保存和员工预检不会误发成功失效事件。导入 commit 成功才通知。
- 异步窗口读取独立拥有页面激活与可见返回版本，旧操作不会在新详情后覆盖新内容；打开窗口前读取真正需要的依赖，并显示读取状态，读取失败不打开旧表单冒充最新数据。
- 复用原模态组件、遮罩、inert、焦点圈和未保存确认；新增 `returnFocus` 支持异步准备后返回原操作按钮。
