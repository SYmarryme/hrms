# 课程 MVP v1.0 实施与运行

范围以用户提供的《HRMS 课程精简版 MVP v1.0 实施规格》及课程 SPEC 为准；旧企业设计文件保留，课程版不实施 CEO 治理流程。原 M00 证据不变，CloudStudio 非前置条件。

## 实施顺序

- A：保留登录、部门、会话策略；Windows 独立虚构演示库及启动工具。
- B：职位、员工、调动归档、CSV/XLSX 预检/原子导入/授权导出。
- C：上海时区、带生效日期的考勤规则、服务端打卡、月报、整日请假与直属主管审批。
- D：整数分薪资及修订历史、SQL 看板、ADMIN 账户维护。
- E：权限、对象范围、事务回滚、持久化、前端类型/构建及演示回归。

测试重点：整批导入失败不得部分提交；主管跨部门/自审与普通员工跨人薪资拒绝；员工调动与离职撤销影响权限；薪资汇总不能泄露给 ADMIN；演示初始化拒绝已有库及模糊路径。

## 已实现的功能

| 模块 | 交付 |
|---|---|
| 部门 | 复用既有搜索、分页、层级、详情、HR 写入、启停保护及 ETag |
| 职位 | 部门内编号唯一、名称/职级/部门/状态过滤、人数、编辑启停；使用中的岗位不能停用或换部门 |
| 员工 | 分页搜索、详情、录入编辑、调动、离职归档和生命周期/归属历史；员工本人、直属主管和 HR 数据范围 |
| 员工数据导入导出（员工档案页） | CSV/XLSX 空白模板、最多100行/2MiB、逐行预检、错误整批不写入、提交重新校验；授权范围导出与公式防护 |
| 考勤 | 上海时区、服务器打卡、重复拒绝；带生效日期的日班规则，迟到/早退/漏卡/月度出勤率及已批请假联动 |
| 请假 | 四类整日假、待审取消、直属部门主管审批、意见/时间留痕；禁止自审、跨部门、工作日重叠和重复审批 |
| 薪资 | HR 月度应发录入/修订、整数分/Decimal、敏感修订历史；员工只读本人；HR 近六个月聚合 |
| 看板 | SQLite 实际员工数、入离职、部门人数、职级比例、出勤、请假类型、HR 薪资趋势；其他角色不返回公司薪资 |
| 用户与权限 | ADMIN 创建账号、员工绑定、四角色和主管直接部门绑定、停用、重置密码并撤销旧会话；禁止本人提权/停用本人；脱敏审计分页查询 |

没有公开注册、JWT、refresh、Cookie 回退或 DEMO_MODE；HR 和 MANAGER 需有效员工任职。
旧 CEO/治理/通用审批表作为原 FK 基线保留，本课程使用直接 MANAGER—部门绑定，未实现那些治理模块。
薪资金额 API 是十进制字符串；显示图表的比例不参与金额计算。
新考勤规则次日或以后生效，保留已生效规则，不能追溯改写原始打卡。
同一天内调动的细节保存在生命周期快照中，日期级当前任职只保留一个有效关系。

```powershell
cd D:\HRMS

python scripts/local.py test
Remove-Item Env:HRMS_DATABASE_PATH,Env:HRMS_PUBLIC_ORIGIN -ErrorAction SilentlyContinue

```

以上命令复用已有 class-one 数据库，本轮不得重新初始化或覆盖它。`demo` 仅用于另行创建全新隔离库，不是更新步骤。

前置：Python3.12、Node22.12+；本轮使用Python3.12.7、Node24.18。无需手工激活虚拟环境或先在 Windows 配置 SQLite。

`demo` 交互输入四个不同的12～128位密码，各确认一次；不接受密码参数、默认密码或非交互输入。
初始化一次性创建完整虚构组织/岗位/3名员工/当前任职/四角色账号及审计；业务数据在一个事务中写入。
账号：`fixture-admin`、`fixture-hr`、`fixture-manager`、`fixture-employee`。这不是正式企业授权或入职审批。

路径固定为 `var/course-demo/<显式名称>/app.sqlite3`；名称仅小写字母、数字及连字符。
同名目录已存在、链接路径、缺少完成标记或数据库配置冲突时拒绝执行，失败半成品不自动覆盖。
`start` 校验私有 manifest 和数据库内虚构审计标记，只启动这个命名库。
前后端均回环监听，页面为 http://127.0.0.1:3000，API 同源代理到127.0.0.1:8000。
所有运行日志、数据库、测试下载文件在忽略的 `var/` 内；不要上传它们。

**停止/切换**：Ctrl+C 停止本地入口；重新执行相同 start 可验证 SQLite 持久化。
原 `var/hrms/app.sqlite3`、原 CloudStudio 库及原终端环境均未由本地入口选中或迁移。
切回旧环境需先停止本地进程，再使用旧环境的原入口和原数据库配置；禁止复制演示库覆盖旧库。

## 文件操作

HR 在员工页下载新的中文 CSV/XLSX 模板，六列表头为：`员工工号、姓名、所属部门、所属职位、入职日期、员工状态`。
**推荐 XLSX**：在“员工导入”页第2至101行填写，部门、职位、员工状态每行都有数据验证下拉。
部门选项为下载时 SQLite 已启用部门；职位选项为已启用、且所属部门也已启用的职位。
选项优先显示名称；重名附部门编号，职位重名附部门编号及职位编号。“业务选项”页可查看业务编号及职位所属部门。
职位下拉列出所有可用职位，填写时请选属于当前部门的职位；服务器会拒绝错配，不会自动更改部门或职位。
列表使用命名区域，无需手工查数据库 ID；模板参考页及下拉元数据不作为服务端可信关联。

**CSV** 使用 UTF-8（推荐BOM）和同样的中文表头；部门填写部门编号或唯一名称，职位填写该部门内的职位编号或唯一名称。
名称或编号有歧义时，请复制 XLSX 中附业务编号的完整选项，不会自动猜测匹配对象。示例仅为课程虚构组织：

```csv
员工工号,姓名,所属部门,所属职位,入职日期,员工状态
COURSE-NEW-001,虚构新员工,FIXTURE-DEV,FIXTURE-STAFF,2026-01-01,在职
```

工号和名称按文本填写，工号前导零须保留；日期用有效 YYYY-MM-DD 日期，XLSX 也可填写真实日期单元格。
员工状态为“待入职 / 试用 / 在职 / 离职办理中”，兼容 PRE_HIRE/PROBATION/ACTIVE/EXIT_PROCESSING；离职请用归档操作。
全部空白员工行可留空，错误行号始终按原文件位置报告，最多100人；不要填到第102行或增加员工字段列。
已有导出文件和旧版完整六列 `employee_no,full_name,department_id,position_id,hire_date,employment_status` 继续兼容，旧ID仍须有效并满足启停与归属检查。
新模板和旧格式不可混搭表头；本次不改变导出字段、数据库结构或权限。文件不导入密码、账号或工资。
选择文件→预检→核对错误行→确认整批导入。预检不是授权票据，提交时后端在同一写事务内重新验证。
部门不存在/停用、职位不存在/停用/不属所选部门、名称歧义、重复工号、日期或状态无效时，页面显示具体行号、字段和原因；任何错误整批不写入。
下载后的启停或组织变化会使旧选项失效，请重新下载；提交时只按当前 SQLite 记录解析，不信任客户端参考页。
非法尺寸、额外列、公式单元格、宏/外部链接、超行数或压缩膨胀的工作簿仍会被拒绝；除模板的“业务选项”页外不接受其他附加工作表。
导出基础档案会重新过滤对象/部门范围，并转义危险表格公式；薪资和账号字段不在导出中。

本次导入易用性修复验证（Windows）：新增20项定向测试通过；公开提交快照后端98/98、前端24/24通过，类型检查和构建通过。
真实Edge两项流程通过，包含中文XLSX下载、错误行号与原因显示、禁止提交错误文件、修正后整批写入，以及原业务链回归。
没有数据库迁移；原有未提交工作保留，运行文件仅存于忽略目录。下方首次MVP的78/23项记录是历史批次数据。

## 最终 UI/UX 改版（2026-10-26）

登录页保留原设计；密码显示按钮是独立按钮，失焦后及键盘操作均可切换。
登录后统一为可折叠左侧导航、顶部可切换/关闭的页面标签、面包屑和宽工作区。
只有当前具体页面有高亮，导航分组不作为选中项。相同页面不重复开标签，工作台常驻。
切换标签保留筛选、页码及未提交表单；有未保存内容时关闭标签需确认。
成功保存只清除对应表单的修改标记，不会清除同页其他草稿；关闭标签后重新打开从服务端读取。

| 角色 | 最终菜单和页面内权限 |
|---|---|
| EMPLOYEE | 工作台、本人考勤、本人请假、本人薪资、本人范围数据看板；没有组织写入、他人工资或公司薪资趋势 |
| MANAGER | 员工自助、直属部门员工档案只读/当前查询导出、直属部门审批、授权范围看板；无 HR 写入/导入/模板下载，不能自审或跨部门审批 |
| HR | 部门、职位、员工档案（含数据导入导出）、考勤规则、薪资录入/修订及 HR 统计；保留本人自助，不自动得到主管审批或账号管理 |
| ADMIN | 工作台、部门与职位基础资料只读、用户管理与审计；管理账号/角色/密码/启停，不自动得到 HR 写入、薪资或工资统计 |

业务自助角色须绑定有效任职；多角色账号按服务端实际有效角色取并集，ADMIN 只有另外实际获得业务角色才显示相应业务内容。
菜单、按钮、编辑表单、操作列及图表均按权限显示；服务端原有角色、本人对象、直属部门和薪资范围校验持续生效。
角色/状态变化撤销会话后，401 会清除所有已开标签及缓存。页面切换/窗口恢复时重新核验身份；可见页面每5秒只读核验一次。
只读核验不推进 last_seen_at，避免后台保活改变24小时空闲超时；正常业务请求保留原会话期限与节流规则。
短暂网络故障先遮挡内容并允许重试，保留尚未提交的草稿；不会因网关故障误判为登出。
员工、审批、薪资、考勤、看板重新激活时会遮挡并刷新授权数据；被调出范围的员工旧详情/审批不再显示。

- 部门与职位独立“编辑”和“停用/恢复”，编辑表单也保留状态；继续使用新读取的 ETag 和后端业务约束。
- 部门、职位、员工提供20/50/100条分页；员工档案和历史状态中文显示。
- 员工导出标注“当前查询”，使用姓名/工号、部门、状态全部条件，导出全部匹配授权记录而非当前一页。主管仍只能导出直属范围。
- 导入按钮简化为“导入”，两种模板按钮左对齐紧邻；服务端原子校验、中文模板及公式防护保留。错误列表显示行号/字段/原因，不显示内部错误码。
- 操作成功反馈约5秒自动移除并释放空间。当天本人打卡状态来自服务器上海日期和本人记录，普通反馈显示时暂时隐藏，反馈结束或关闭后恢复。
- 回到考勤标签、窗口恢复、跨上海日期以及重复打卡被拒绝后，重新读取当天状态；HR 员工筛选不影响本人的长期打卡提示。
- 重复打卡、请假重叠、重复审批等显示可操作的中文原因；未知服务端/网关消息仅显示安全通用提示。
- 请假、薪资显示员工姓名/工号，审批/审计及工资修订显示操作账号。API 的 UTC 时间戳显式带 Z，前端统一按 Asia/Shanghai 格式化，不修改数据库时间。

本次没有新增数据库迁移、业务模块、公告、通知、补卡、薪资计算或部署审批流程；不重新初始化已有演示库。

### 已定位的交互原因

现在工作区复核使用 visibility 隐藏并设置 inert/aria-hidden，范围刷新期间暂留实测页面高度，包含子元素外边距；提示脱离文档流。仍遮挡未重新确认的数据，不移除后端鉴权或刷新，不调用 scrollTo 强行回位。没有证据显示组件因下载被重建或按钮永久禁用；回顶会让底部按钮离开原位置。

A–F 压力测试还定位到独立浏览器边界：接口返回200、文件锚点已执行且有用户激活，但一秒内第11次突发下载不产生下载事件。这与 [Chromium LocalFrame 下载突发保护](https://chromium.googlesource.com/chromium/src/+/70bd53b1fffc88167c049e6994e5167a3a78da03/third_party/blink/renderer/core/frame/local_frame.cc#3927) 的10次/1秒机制吻合，不能将它当成接口或按钮永久失效。文件启动现在至少间隔150ms，调用方等待启动后在 finally 恢复状态；首个文件无额外等待，没有关闭浏览器保护。重复触发防重、显式 type=button 和导入重新选择状态保持一致。
四轮 A–F 原用例全部通过，逐个核验实际 CSV/XLSX 下载文件、请求数和失败恢复，而非只检查 click。每轮19个文件实际下载成功，另有一次受控503失败；取消/无效文件预检、关闭后重开、筛选/页大小/标签保持均覆盖。临时事件诊断已移除。
