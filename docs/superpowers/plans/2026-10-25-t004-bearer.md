# T-004 minimal Bearer compatibility implementation plan

**Goal:** An independent Edge HTTPS page test must observe correct/missing/wrong synthetic Bearer as 200/401/401.

**Architecture:** Browser generates a random token in function-local memory and registers only its SHA-256 digest
in a bounded, expiring backend memory context. An unrelated random context ID identifies the test endpoint;
the ID is not a token and cannot authenticate a request. Neither endpoint returns token text.
This is an anonymous synthetic compatibility fixture with no HRMS permissions, users, sessions or business data.

**Tech Stack:** Existing Vue render functions, Web Crypto/fetch, FastAPI and Python standard library.
No dependencies, environment secrets, new start.sh or proxy changes.

**Spec:** User's current T-004 Bearer request; existing acceptance/security constraints remain effective.

## Constraints and review focus

- Runtime execution is CloudStudio Ubuntu and actual Edge only; Windows static preparation cannot establish PASS.
- No Cookie/storage/URL token persistence or token output; response/report/error fields are fixed safe projections.
- No Authorization tracing, token length/header metadata diagnostics, production auth or Cookie redesign.
- Preserve Vite Host checks, 3000 public/8000 loopback, all original seven Cookie regressions, SQLite evidence.
- Three actual HTTP outcomes must all match; redirect/network/invalid fixture/expired context must fail.
- Token digest registration has no business authority; bounded TTL contexts prevent unlimited memory growth.
- Existing Cookie and port limitations keep T-004 BLOCKED even if this separate experiment passes.

## Delivery steps

1. Write direct ASGI regressions for the three statuses, absent context, unsupported credentials and expiry.
   Also check that malformed setup input is rejected without reflecting arbitrary text.
   Runtime red/green verification remains NOT_RUN under the Windows-only preparation constraint.
2. Add two isolated experiment routes in backend.py; do not alter existing Cookie routes/middleware.
3. Add a separate button/result in main.ts, same-origin credentials=omit, no redirects or raw diagnostics.
4. Supply a CloudStudio-only regression wrapper and exact setup/start/Edge acceptance instructions.
5. Static syntax/privacy review, independent read-only review, public-file audit, commit and fast-forward sync.

Only file preparation, review and static checks can be completed locally. Do not mark the experiment or T-004 passed.
